## Quick verification (no sequence searches)

From `analyses/figure4`, after installing `requirements-lock.txt`:

```sh
python -m unittest discover -s reconstruction/tests -v
python reconstruction/bin/validate_evidence.py --results reconstruction/evidence
python reconstruction/bin/validate_evidence.py --results reconstruction/full_panel_repeat/results
python reconstruction/bin/compare_repeat.py --reference reconstruction/evidence --repeat reconstruction/full_panel_repeat/results
```

These commands check the archived evidence, rejection safeguards, six earlier
repeat records, the new full-panel repeat, and agreement with the plotting inputs. Tests decompress the
40 supplied assembly files into a temporary directory and verify the original
FASTA-byte hashes. They do **not** run a new whole-panel search.

## Run the reconstruction from sequences

No private Desktop paths or network downloads are needed. Restore the inputs
to a new directory, then run the preserved search procedure:

```sh
python reconstruction/bin/prepare_inputs.py --output-dir build/rbh-inputs
python reconstruction/bin/run_rbh.py --project-root build/rbh-inputs --outdir build/rbh-run --proteome-cache build/rbh-proteomes.json --time-budget 60
```

Repeat the **second command** until it reports all 40 genomes complete and
writes the aggregate evidence. The budget is checked between genomes, not a
hard wall-clock limit; prediction and an individual search may exceed it.
Omit `--time-budget 60` to run uninterrupted. The recorded search phase took
approximately 13 minutes on its original host; other computers may differ.
Then validate the new results:

```sh
python reconstruction/bin/validate_evidence.py --results build/rbh-run
```

The input-restoration step uses the original relative directory layout solely
to preserve the reviewed runner's interface. Always use a fresh output and
cache path for a new run. Existing-output, checkpoint, and cache compatibility
checks precede output initialization. Regenerated-query identity is checked
later, before searches, so this is not a claim that every possible refusal
occurs before any write. Do not point the runner at the saved evidence folder.

## What the reconstruction means

The original record describes single-sequence profiles and `hmmsearch` in both
directions at E < 1e-5. The original executable and cell-level hit tables were
not retained. The reconstruction uses Pyrodigal 3.7.1, trained separately on
each genome with `meta=False`, and PyHMMER 0.12.2. All 45 query sequences were
verified individually by identifier; regenerated target proteomes total
239,999 proteins. Matching counts and deterministic regeneration do not prove
byte identity with the historical target proteomes.

Four choices are explicit reconstruction settings, not recovered facts:

- Reverse searches use the complete BAA-554 proteome (5,937 proteins).
- Forward searches use each genome separately, with its actual database size.
- Lowest sequence E-value ranks first, then highest bit score; unresolved exact
  ties are retained in the evidence and excluded from unique reciprocal calls.
- No alignment-coverage filter is applied; coordinates and coverage are saved.

Seed 42 and observed builder/pipeline settings are recorded. `symfrac` and
`fragthres` remain constructor-default declarations because the installed API
does not expose them for readback. The saved profiles are the 45 **forward**
query profiles; reverse profiles can be regenerated by the runner.

The six saved repeat records match the corresponding primary-run evidence.
Those records are a **bounded 6-of-40 repeat**, not a full-panel run. The separate
`full_panel_repeat/` deposit now records a complete 40-genome local repeat.
Matching all row and column totals cannot establish historical cell or protein
pair identity. Panel (c) continues to plot the unchanged historical counts.

## Files and provenance

- `evidence/`: primary reconstructed calls, raw hits, matrix, profiles, input
  inventory, query checks, and version/settings records.
- `repeat_evidence/`: six repeat checkpoints, their original hashes, and one
  additional hardened-runner checkpoint for ALG19.
- `full_panel_repeat/`: subsequent complete 40-genome repeat, original detailed results, logs, and explicit comparisons.
- `inputs/assemblies/`: 40 deterministically compressed assembly FASTAs.
- `bin/`: reviewed shared validator, runner, and input-restoration helper.
- `tests/`: 54 reconstruction checks, four integration checks, and five full-repeat comparison checks.

The raw scientific evidence is byte-preserved from the reviewed packages.
Non-portable directory descriptions in the repeat summary were replaced with
portable descriptions; scientific values and checkpoint hashes were retained.
Original source hashes and public-copy hashes are recorded in
`evidence/source_files.json`. The original `environment.json` field
`elapsed_s=56.1` measures the final invocation only, **not** total execution;
the supplemental environment record and this note correct its interpretation.

The packaging pass changed test-data locations and narrowed runner comments;
it did not change search calculations or the shared validation core. The
assembly FASTAs reconstruct byte-identically after decompression. Source
archives remain preserved outside this repository. No whole-study replication,
licence approval, public release, or DOI deposition is implied.
