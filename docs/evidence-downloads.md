# Supporting evidence downloads

Download individual packages from the eight tagged evidence releases below, or get the [complete v1.0.0 Zenodo archive](https://doi.org/10.5281/zenodo.23219657). The 17 packages have companion instructions, checksums, and indexes, for 44 named files in total.

For the manuscript version of [Supplementary Table S2 and its caption](../supporting-analysis/manuscript-tables/README.md), use the current table in this source release. It preserves the 16 exclusion decisions and distinguishes the saved BAA-554 comparison from the two GTDB-Tk FastANI results. The same directory provides a dated strain-to-BioSample and assembly crosswalk for all 40 panel rows.

## Choose a package

## Download and verify

1. Open the release and download the exact archive named in the table. Each public evidence tag points to the v1.0.0 source snapshot. The named asset and its checksum identify the evidence package in this release.
2. Download the linked checksum file and verification instructions into the same new folder. Follow the instructions for that release; a shared checksum file may cover several companion assets.
3. Verify the downloaded bytes before extraction. On macOS, use `shasum -a 256 -c filename.sha256` for an individual checksum file, or follow the package instructions for `SHA256SUMS.txt`. Every requested file must match.
4. Extract into an empty folder and read the package README before running any included verifier or optional analysis. Check whether the command verifies saved evidence or performs a new computation.

Native antiSMASH results require the companion verification kit. Keep packages from different releases in separate folders because names such as `VERIFY.txt`, `package-index.json`, and `SHA256SUMS.txt` recur.

Some archived README and verification files describe their preparation-time status, including “not yet deposited” or “integration pending.” Those dated status statements are superseded by this guide and the current release notes. The archived scientific methods, input identities, and limitations remain applicable. For v1.0.0, the 18-mer/crosswalk package READMEs and checksum documentation were revised. Its input sequences, analysis code, and results retain their original bytes. Use the checksums in this guide’s linked files.

The family-search package’s `links/external-inputs.json` records the original Figure 3 review commit. Use [Figure 3 at v1.0.0](https://github.com/pushkarsai-dev/delftia-comparative-genomics/tree/v1.0.0/analyses/figure3) for the public copy. Its verifier reads the local files and checksums.

## Coverage and limitations

The deposited scopes for #1 and #3–26 are preserved. Original batch-specific SeqCoast processing/QC records (#2) remain unavailable; optional historical diagnostics (#28) have no dedicated deposit. The packages do not recover every historical executable, service environment, or cache. In particular, native KBase objects and available provenance are preserved, while the original species-tree alignment and exact historical FastTree point version remain unavailable.

For study sequencing reads, use [SRA study SRP726995](https://www.ncbi.nlm.nih.gov/sra/?term=SRP726995). The sequencing-support package supplies sample assignments and accession mappings. The archive excludes full read deliveries and raw instrument signals.
